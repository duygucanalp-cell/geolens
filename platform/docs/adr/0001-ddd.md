# ADR-001 · Domain-Driven Design (DDD) Yaklaşımı

| Alan | Değer |
|---|---|
| ADR ID | ADR-001 |
| Durum | Kabul |
| Tarih | 22.07.2026 |
| Karar veren | TL |
| İlişkili | 0302, 0303, 0305, 0502 |

---

## Bağlam

GeoLens Platform'un alan karmaşıklığı (AI görünürlük ölçümü, skorlama, çok kiracılı izolasyon) geleneksel CRUD yaklaşımıyla yönetilemeyecek kadar yüksektir. Yazılımın uzun vadeli bakımını ve evrimini garanti altına almak için bir domain modelleme stratejisi seçilmelidir.

---

## Karar

**Domain-Driven Design (DDD) prensipleri benimsenmiştir.**

| Bileşen | Yaklaşım |
|---------|----------|
| **Bounded Context** | 6 bağlam (BC1-BC6) |
| **Aggregate Root** | 11 toplam kökü |
| **Domain Events** | 21 alan olayı (outbox pattern ile) |
| **Repository** | sqlc-tabanlı repository katmanı |
| **Domain Services** | 15 durumsuz alan hizmeti |

---

## Alternatifler

| Seçenek | Red nedeni |
|---------|------------|
| CRUD-only (anemic domain) | İş mantığı servis katmanına yayılır, domain zenginliği kaybolur |
| Active Record | Go'da yaygın değil, test edilebilirlik düşük |
| Event Sourcing (tam) | V1 için aşırı karmaşık; audit_log için kısmi ES (yalnız-ekleme + karma zinciri) kabul |

---

## Sonuçlar

- 0302 Domain Model DDD prensipleriyle yazılmıştır
- 0303 Aggregates transaction sınırlarını çizer
- 0305 Bounded Contexts modül sınırlarını tanımlar
- 0404 Test stratejisi DDD katmanlarına göre yapılandırılır
